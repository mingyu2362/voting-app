# 실시간 결과 갱신에 WebSocket/SSE 대신 폴링 사용

결과는 서버가 변경 사항을 푸시하는 대신, 클라이언트가 3~5초마다 다시 요청하는 방식으로 준실시간 갱신된다.

Vercel에 배포하기 때문에 폴링을 선택했다 — Vercel의 서버리스 함수는 WebSocket이나 SSE처럼 오래 유지되는 연결에 적합하지 않아, 제대로 하려면 Edge Runtime이나 별도 인프라가 필요하다. 득표수 표시가 몇 초 정도 지연되는 것은, Neon 위에서 단순한 요청/응답 폴링으로 구현했을 때 얻는 운영상의 단순함을 고려하면 받아들일 만한 트레이드오프다.
