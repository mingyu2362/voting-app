# 설문 마감 시간 + 결과 그래프

Status: ready-for-agent

## Problem Statement

동아리 회장은 "투표가 계속 열려있어서 사람들이 참여를 안 한다"고 지적했다. 지금 앱은 설문에 마감 개념이 없어 무기한 열려있고, 그래서 급하게 참여해야 할 이유가 없다. 또한 결과가 숫자로만 표시돼서 한눈에 비교하기 어렵다.

## Solution

설문 생성 시 마감 시각을 선택적으로 지정할 수 있게 하고, 마감이 다가오면 카운트다운으로 참여를 독려한다. 마감이 지나면 자동으로 투표를 막고 결과를 누구에게나 공개한다. 결과는 기존 숫자 표시에 더해 막대그래프로도 보여준다.

## User Stories

1. As an 운영자, I want 설문을 만들 때 마감 시각을 선택적으로 지정, so that 참여 기한을 명확히 정할 수 있다.
2. As an 운영자, I want 마감 시각을 지정하지 않으면 설문이 무기한 진행, so that 기존처럼 기한 없는 설문도 계속 만들 수 있다.
3. As an 운영자, I want 이미 만든 설문의 마감 시각을 나중에 바꾸거나 없앨 수 있는 것, so that 일정 변경에 유연하게 대응할 수 있다.
4. As an 운영자, I want 날짜와 시각을 직접 선택해서 마감을 지정, so that 동아리 일정(회의/행사 시각)에 정확히 맞출 수 있다.
5. As an 운영자, I want "지금 마감하기" 버튼으로 마감 시각과 무관하게 즉시 설문을 닫을 수 있는 것, so that 무기한으로 열어둔 설문도 삭제하지 않고 원할 때 닫을 수 있다.
6. As a 참여자, I want 마감 시각이 지난 설문에서 투표 버튼이 비활성화되고 안내 문구가 보이는 것, so that 왜 투표할 수 없는지 바로 이해할 수 있다.
7. As a 참여자, I want 마감된 설문은 투표 여부와 상관없이 결과를 볼 수 있는 것, so that 참여하지 않았어도 최종 결과를 확인할 수 있다.
8. As a 참여자, I want 마감 전 설문 상세 페이지에서 마감까지 남은 시간을 카운트다운으로 볼 수 있는 것, so that 얼마나 급하게 투표해야 하는지 체감할 수 있다.
9. As a 참여자, I want 설문 목록에서 진행 중인 설문이 먼저 보이고 마감된 설문은 아래로 분리되어 보이는 것, so that 지금 참여 가능한 설문을 빠르게 찾을 수 있다.
10. As a 참여자, I want 각 선택지의 결과를 막대그래프로도 볼 수 있는 것, so that 숫자를 일일이 비교하지 않아도 한눈에 결과를 파악할 수 있다.
11. As a 참여자, I want 그래프와 함께 기존의 득표수·퍼센트 숫자도 계속 보이는 것, so that 정확한 수치도 놓치지 않고 확인할 수 있다.
12. As an 운영자, I want 마감된 설문의 마감 시각을 미래로 다시 연장할 수 있는 것, so that 착오로 일찍 마감했거나 기간을 늘리고 싶을 때 되돌릴 수 있다.
13. As a 참여자, I want 마감이 연장되어 설문이 다시 진행 중으로 바뀌면 결과가 다시 "투표해야 보임" 규칙으로 돌아가는 것(정상 동작), so that 마감 전/후의 결과 공개 규칙이 항상 일관되게 적용된다.
14. As a 개발자, I want 퍼센트 계산과 목록 정렬 로직이 순수 함수로 분리되어 있는 것, so that 실제 시간이 지나가길 기다리거나 DB 없이도 이 로직들을 빠르고 안정적으로 테스트할 수 있다.
15. As a 개발자, I want 마감 판단 로직이 현재 시각을 주입받는 형태로 만들어진 것, so that 테스트에서 "마감 시각을 막 지난 시점" 같은 상황을 실제로 기다리지 않고 재현할 수 있다.
16. As an 운영자, I want 결과 페이지에서 투표 여부와 무관하게 항상 결과(숫자+그래프)를 볼 수 있는 것(기존 규칙 유지), so that 마감 전후 상관없이 진행 상황을 모니터링할 수 있다.
17. As 누구든, I want 투표가 0건인 설문의 결과 화면에서 퍼센트가 에러 없이 0%로 표시되는 것, so that 아직 아무도 투표하지 않은 설문의 결과도 깨지지 않고 보인다.
18. As a 참여자, I want 마감 시각이 없는(무기한) 설문의 상세 페이지에는 카운트다운이 아예 표시되지 않는 것, so that 존재하지 않는 마감을 향한 카운트다운을 보고 혼란스럽지 않다.
19. As a 참여자, I want 마감 직전에 페이지를 열어둔 채로 있다가 마감 시각을 넘긴 뒤 투표를 시도해도 서버가 이를 거부하는 것, so that 클라이언트의 카운트다운 표시와 무관하게 마감 규칙이 실제로 지켜진다.

## Implementation Decisions

- **스키마**: `polls` 테이블에 nullable `closes_at TIMESTAMPTZ` 컬럼을 추가하는 마이그레이션. 기존 행은 기본값 NULL(무기한).
- `createPoll`에 선택적 `closesAt: Date | null` 파라미터를 추가한다.
- 새 서버 액션 `updatePollDeadline(sessionToken, pollId, closesAt, now?)`: 운영자 세션이 필요하며 `closes_at`을 지정한 값(또는 null)으로 갱신한다. "지금 마감하기"는 이 함수를 `closesAt = now`로 호출하는 것과 동일하게 구현한다.
- **마감 여부 판단**: 별도로 저장되는 상태 필드 없이 `closes_at !== null && closes_at <= now`로 매 요청마다 계산한다(ADR 0004). `now`는 함수 인자로 주입 가능하게 만들어 테스트에서 결정적으로 제어한다 — 기존 `isOperatorSession(token, now)`와 같은 패턴.
- `getPoll`의 `resultsVisible` 계산을 `hasVoted || isOperatorSession(...) || isClosed`로 확장한다(ADR 0003 — 마감되면 결과가 공개되고, 마감이 미래로 연장되면 다시 비공개로 돌아간다. 영구 공개 플래그는 두지 않는다).
- `PollView`에 `closesAt: string | null`, `isClosed: boolean` 필드를 추가해 클라이언트가 카운트다운/버튼 비활성화/배지에 사용한다.
- `castVote`는 마감된 설문에 대한 투표 시도를 거부한다(새 에러 케이스, 예: `"poll_closed"`). 클라이언트의 버튼 비활성화와 별개로 서버에서 반드시 재검증한다.
- `listPolls`가 각 설문의 `closesAt`/`isClosed`를 함께 반환하고, "진행중 먼저 → 마감은 아래"로 정렬한다. 정렬 로직은 별도의 순수 함수로 분리한다(예: `sortPollsByStatus(polls, now)`).
- 퍼센트 계산 로직(`votes / totalVotes`, 총 투표 0건일 때 0%, 반올림 규칙)을 `getPoll` 내부에서 분리해 별도 순수 함수로 추출한다(예: `computePercent(votes, totalVotes)`).
- **결과 화면(UI)**: 기존 득표수+퍼센트 숫자 표시와 함께, 선택지별 득표 비율을 보여주는 막대그래프를 CSS/SVG로 직접 구현해 추가한다(새 의존성 없음, 숫자 표시를 대체하지 않음).
- **카운트다운(UI)**: `closesAt`이 있는 설문의 상세 페이지에서 클라이언트가 1초 간격으로 로컬 시계 기준 "남은 시간"을 계산해 표시한다 — 3~5초 서버 폴링과는 별개의 로컬 타이머다. `closesAt`이 없는 설문에는 카운트다운을 아예 렌더링하지 않는다.
- **투표 버튼(UI)**: `isClosed`가 true면 버튼을 숨기지 않고 비활성화 상태로 표시하며 안내 문구를 함께 보여준다.
- **운영자 대시보드(UI)**: 설문별로 마감 시각을 표시/수정할 수 있는 입력과 "지금 마감하기" 버튼을 추가한다.

## Testing Decisions

- 새 시드를 만들지 않는다 — 기존 서버 액션 계층 시드(Vitest + 실제 테스트 DB, `TEST_DATABASE_URL`)를 그대로 확장한다.
- 마감 관련 로직(`getPoll`의 `isClosed`/`resultsVisible`, `castVote`의 마감 거부, `updatePollDeadline`)은 `now`를 주입받는 파라미터를 통해, 실제 시간을 기다리지 않고 "마감 직전/직후" 같은 경계 조건을 결정적으로 테스트한다.
- 퍼센트 계산(`computePercent`)과 목록 정렬(`sortPollsByStatus`)은 DB나 세션 없이 동작하는 순수 함수로 분리해서, 입력→출력만 검증하는 단위 테스트를 별도로 작성한다. 특히 총 투표수 0건일 때 0%를 반환하는지, 반올림이 스펙(소수 첫째자리)대로 되는지, 진행중/마감 설문이 올바른 순서로 정렬되는지를 검증한다.
- 그래프(막대그래프 렌더링)와 카운트다운 컴포넌트는 자동화 테스트 대상에서 제외한다 — 기존 스펙과 동일하게 UI 렌더링 자체는 수동 확인으로 충분하다고 판단한다.
- 프라이어 아트: `tests/actions/auth.test.ts`의 `isOperatorSession(token, now)` 주입 패턴, `tests/actions/get-poll.test.ts`/`cast-vote.test.ts`의 기존 게이팅 테스트 구조.

## Out of Scope

- 마감 임박 알림(이메일/푸시 등).
- 그래프 커스터마이징(색상 선택, 차트 종류 변경 등) — 기본 막대그래프 하나만 구현.
- 마감 시각 변경 이력(누가 언제 얼마나 연장/단축했는지) 기록 — 현재 값만 저장.
- 카운트다운 이외의 실시간 알림(예: 마감되는 순간 자동 알림/이벤트) — ADR 0004에 따라 이벤트 기반 동작은 범위 밖.

## Further Notes

- 용어는 `CONTEXT.md`의 갱신된 "설문(Poll)"/"마감(Closed)" 정의를 따른다.
- 마감 후 결과 재비공개 규칙은 `docs/adr/0003-live-computed-result-visibility.md`, 마감 판단을 크론 없이 요청 시점에 계산하기로 한 이유는 `docs/adr/0004-deadline-computed-not-scheduled.md` 참고.
- 이 기능은 기존 MVP(`.scratch/voting-app/`)를 확장하는 것으로, 같은 서버 액션 계층과 스키마를 이어서 사용한다.
