# 투표 앱 (Voting App) MVP

Status: ready-for-agent

## Problem Statement

동아리 회장은 안건이 생길 때마다 사람들의 의견을 모아 결정을 내리고 싶어 한다. 지금은 이를 위한 전용 도구가 없어 메신저나 종이 등으로 즉흥적으로 처리하고 있고, 그 결과 투표를 시작하기도, 결과를 취합하기도, 중복 투표를 막기도 번거롭다.

동아리원(참여자) 입장에서는 회원가입이나 로그인 없이 가볍게 의견을 낼 수 있어야 하고, 자신이 투표한 뒤에는 바로 결과를 확인할 수 있어야 한다.

## Solution

운영자(동아리 회장 등)가 공유 비밀번호로 로그인해 질문과 선택지로 구성된 설문을 만들고 삭제할 수 있는 간단한 웹 앱을 만든다. 참여자는 로그인 없이 접속해 원하는 설문의 선택지 하나를 골라 투표하고, 투표 직후 득표수와 퍼센트로 표시되는 결과를 실시간(폴링)으로 확인할 수 있다. 투표 전에는 결과가 전혀 노출되지 않는다.

## User Stories

1. As an 운영자, I want 공유 비밀번호로 로그인, so that 인가된 동아리 관계자만 설문을 관리할 수 있다.
2. As an 운영자, I want 로그인 세션이 1일 동안 유지되는 것, so that 설문을 관리하는 동안 비밀번호를 반복 입력하지 않아도 된다.
3. As an 운영자, I want 로그아웃 기능, so that 공용 컴퓨터에서 세션을 안전하게 종료할 수 있다.
4. As an 운영자, I want 질문과 고정된 선택지 목록으로 설문을 생성, so that 특정 안건에 대한 투표를 시작할 수 있다.
5. As an 운영자, I want 생성된 설문의 질문/선택지가 이후 수정되지 않는 것, so that 이미 투표를 시작한 참여자들에게 공정성이 유지된다.
6. As an 운영자, I want 내가 만든 설문을 삭제, so that 더 이상 필요 없거나 실수로 만든 설문을 정리할 수 있다.
7. As an 운영자, I want 설문을 삭제하면 그 설문의 투표 기록도 함께 영구 삭제되는 것, so that 고아 데이터가 남지 않는다.
8. As an 운영자, I want 내가 만든 모든 설문의 목록을 확인, so that 여러 개의 진행 중/과거 설문을 한눈에 관리할 수 있다.
9. As an 운영자, I want 내 투표 여부와 상관없이 모든 설문의 실시간 결과를 볼 수 있는 것, so that 투표 진행 상황을 모니터링할 수 있다.
10. As a 참여자, I want 현재 존재하는 모든 설문의 목록을 확인, so that 참여할 설문을 찾을 수 있다.
11. As a 참여자, I want 설문의 질문과 선택지를 확인, so that 무엇에 투표할지 결정할 수 있다.
12. As a 참여자, I want 선택지 하나를 골라 투표를 제출, so that 내 의견을 남길 수 있다.
13. As a 참여자, I want 같은 브라우저로 같은 설문에 두 번 투표할 수 없는 것, so that 결과의 공정성이 지켜진다.
14. As a 참여자, I want 계정이나 개인정보 없이 익명으로 투표, so that 부담 없이 참여할 수 있다.
15. As a 참여자, I want 한 번 제출한 투표를 이후에 변경할 수 없는 것, so that 설문 결과가 안정적이고 신뢰할 수 있게 유지된다.
16. As a 참여자, I want 투표하기 전에는 총 투표 수를 포함해 어떤 결과도 보이지 않는 것, so that 다른 사람의 선택에 영향을 받지 않고 고를 수 있다.
17. As a 참여자, I want 투표 직후 바로 결과를 확인, so that 내 선택이 전체 결과와 어떻게 비교되는지 알 수 있다.
18. As a 참여자, I want 각 선택지의 득표수와 퍼센트를 함께 확인, so that 결과를 한눈에 이해할 수 있다.
19. As a 참여자, I want 결과 화면이 새로고침 없이 몇 초마다 자동으로 갱신되는 것, so that 실시간에 가깝게 흐름을 지켜볼 수 있다.
20. As 누구든(사이트 방문자), I want 계정 생성 없이 앱을 이용할 수 있는 것, so that 참여 장벽이 최소화된다.
21. As an 운영자, I want 공유 비밀번호가 클라이언트 코드나 로그에 절대 노출되지 않는 것, so that 인가되지 않은 사람이 운영자 권한을 얻을 수 없다.
22. As a 개발자, I want 설문 생성/삭제, 투표, 결과 조회, 운영자 로그인이 하나의 서버 사이드 모듈(서버 액션 계층)을 통해서만 이루어지는 것, so that DB를 모킹하지 않고 실제 DB에 대고 이 모듈만 테스트해도 전체 동작을 검증할 수 있다.

## Implementation Decisions

**스키마**
- `Poll`: `id`, `question`(text), `created_at`.
- `Choice`: `id`, `poll_id`(FK → Poll, `ON DELETE CASCADE`), `label`(text), 표시 순서(`position` 등).
- `Vote`: `id`, `poll_id`(FK → Poll, `ON DELETE CASCADE`), `choice_id`(FK → Choice), `voter_token`(text). `(poll_id, voter_token)`에 유니크 제약을 걸어, 애플리케이션 레벨 체크와 별개로 DB 레벨에서도 중복 투표를 막는다.
- 운영자(Operator)를 위한 테이블은 없다 — 공유 비밀번호는 환경 변수(`ADMIN_PASSWORD`)로만 존재하고, 운영자별 신원은 저장하지 않는다.

**참여자 식별 (voter_token)**
- 최초 방문 시 서버가 임의의 opaque한 `voter_token`(예: UUID)을 발급해 httpOnly 쿠키로 심는다. 설문마다 별도 쿠키를 두지 않고, 앱 전체에서 재사용되는 쿠키 하나로 처리한다.
- 특정 브라우저가 특정 설문에 투표했는지는 이 쿠키 값과 `Vote` 테이블의 `(poll_id, voter_token)` 조합 존재 여부로 판단한다.

**운영자 세션**
- `login` 서버 액션이 제출된 비밀번호를 `ADMIN_PASSWORD`와 상수 시간 비교(constant-time compare)로 검증한다.
- 성공 시, 서버 비밀 키로 서명한 httpOnly 세션 쿠키를 발급한다. 토큰 자체에 24시간 만료 시각을 담아, 별도의 서버 사이드 세션 저장소 없이 자체적으로 만료되게 한다.
- `createPoll`, `deletePoll` 등 운영자 전용 액션은 실행 전 이 서명된 쿠키를 검증한다.

**설문 목록/결과 공개 규칙**
- `listPolls`는 모든 설문의 `id` + `question`만 반환한다 (득표수 없음).
- `getPoll(pollId)`는 질문과 선택지를 반환하며, 요청자의 `voter_token`으로 해당 설문에 대한 `Vote` 레코드가 존재하면 선택지별 득표수·퍼센트·총 투표수를 함께 반환하고, 없으면 숫자 데이터를 전혀 포함하지 않는다.
- 3~5초 폴링에 쓰이는 결과 조회도 동일한 "게이트된" 응답 형태를 사용한다.

**투표 제출**
- `castVote(pollId, choiceId)`는 `voter_token` 쿠키를 읽고(없으면 새로 발급), 사전 체크 + DB 유니크 제약(`poll_id`, `voter_token`)으로 동일 설문 재투표를 거부한다. 성공 시 방금 채워진 게이트된 결과를 반환하고, 실패 시 "이미 투표함" 에러를 반환한다.

**설문 삭제**
- `deletePoll(pollId)`는 유효한 운영자 세션을 요구하며, `Poll` 행을 삭제하면 `ON DELETE CASCADE`로 연결된 `Choice`/`Vote`가 함께 삭제된다.

**설문 생성**
- `createPoll(question, choices[])`는 유효한 운영자 세션을 요구하며, `Poll` 1개 행과 `Choice`(최소 2개) 행들을 하나의 트랜잭션으로 생성해 설문이 절반만 생성된 상태로 남지 않게 한다.

**실시간 갱신 (클라이언트)**
- 설문 상세 페이지는 참여자가 투표를 완료한 이후에만 `getPoll`/결과 조회를 3~5초 간격으로 반복 호출한다 (`setInterval` 기반 재요청). 투표 전에는 폴링을 시작하지 않는다.

**결과 표시 형식**
- 선택지별로 득표수와 퍼센트(득표수 / 총 투표수)를 함께 숫자로 표시한다. 그래프/차트는 이번 스펙 범위에 포함하지 않는다.

## Testing Decisions

- 테스트 러너로 **Vitest**를 새로 도입한다 (Next.js 서버 액션/TypeScript와 궁합이 좋고, 브라우저 없이 서버 액션 계층만 테스트하기에 적합).
- 모든 테스트는 서버 액션 모듈을 **직접 import해서 호출**하며, DB 클라이언트를 모킹하지 않는다. 대신 Neon의 별도 테스트 브랜치를 가리키는 `TEST_DATABASE_URL`을 사용하고, 테스트 사이/전에 관련 테이블을 정리(truncate)한다.
- 좋은 테스트의 기준: 액션 호출의 입력과 반환값(또는 이어지는 다른 액션 호출 결과)만으로 외부에서 관찰 가능한 동작을 검증한다 — 내부 SQL 문이나 테이블 구조를 직접 검증하지 않는다. 예: `createPoll` → `castVote` → 같은 토큰으로 `castVote` 재시도 → `getPoll`을 호출해 각 단계의 반환 값/에러를 확인.
- 테스트 대상 모듈: 설문/투표 서버 액션 모듈, 운영자 인증(로그인/로그아웃/세션 검증) 모듈.
- 이 레포에 기존 테스트 선례는 없다 — 이 스펙이 첫 테스트 컨벤션을 확립한다.
- UI 컴포넌트(페이지, 폼, 폴링 훅) 자체의 자동화 테스트는 이번 스펙 범위 밖이며, MVP 단계에서는 브라우저 수동 확인으로 충분하다.

## Out of Scope

- 설문 마감 시각/진행중-마감 상태 (추후 단계에서 별도 구현 예정).
- 결과 그래프/차트 시각화 (추후 단계, 지금은 숫자(득표수+퍼센트)만).
- 여러 운영자 계정/운영자별 신원 (공유 비밀번호 1개만).
- 생성 후 설문 질문/선택지 수정.
- 이미 제출한 투표의 변경.
- 쿠키 기반 익명 토큰 이외의 참여자 식별 수단 (계정, 이메일, 이름 등 없음).
- WebSocket/SSE 등 서버 푸시 기반 실시간 갱신 (ADR 0002 참고).

## Further Notes

- 용어는 `CONTEXT.md`에 정의된 대로 사용한다 (설문/Poll, 선택지/Choice, 투표/Vote, 운영자/Operator, 참여자/Voter) — 코드/티켓에서 다른 동의어로 바꿔 쓰지 않는다.
- 참여자 중복 방지를 계정이 아닌 쿠키 기반으로 한 이유는 `docs/adr/0001-cookie-based-vote-deduplication.md`, 실시간 갱신을 폴링으로 택한 이유는 `docs/adr/0002-polling-for-realtime-results.md` 참고.
- 배포 대상은 Vercel + Neon Postgres. `@neondatabase/serverless`는 이미 설치돼 있고, `.env.local`에 `DATABASE_URL`도 이미 존재한다 (ORM은 아직 미도입 상태).
